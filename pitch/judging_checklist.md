# Judging Checklist

## Before Submission

- [ ] Demo runs end-to-end without crashes
- [ ] Clear problem statement (30 sec)
- [ ] Live demo prepared (not just slides)
- [ ] Monad integration explained (wallet, contract, or tx)
- [ ] AI/agent component is core (not bolted on)
- [ ] GitHub repo link ready
- [ ] README with setup instructions

## What Judges Look For

| Criteria | How We Address It |
|----------|-------------------|
| Innovation | Multi-agent + on-chain reputation |
| Technical depth | LangGraph-ready pipeline, RAG, provider abstraction |
| Demo quality | DemoPanel with animated steps |
| Monad usage | Wallet agent, testnet txs, reputation contract |
| Completeness | Full-stack: UI + API + agents + docs |

## Score Yourself

- [ ] Problem is clear and relatable
- [ ] Solution works live
- [ ] Blockchain adds real value (not gimmick)
- [ ] Code is readable and documented
- [ ] Team can explain architecture

## Common Pitfalls to Avoid

- Demo depends on flaky testnet → have mock fallback
- No clear user value → lead with use case
- Single chatbot disguised as "agent" → show pipeline
- Private keys in repo → use .env only
